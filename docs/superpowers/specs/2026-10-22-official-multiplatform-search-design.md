# 帮你省：三平台官方搜索与模型决策设计

状态：用户已确认设计及开发计划，当前实施中。真实平台仍待凭证与联调验收。

## 目标与范围

用户已明确要求淘宝、京东、拼多多同时接入，通过多路搜索让模型比较并给出最合适的方案，并选择官方接口作为数据来源。

本次保留抽纸、卷纸、洗衣液三个品类，扩展现有 Next.js 应用。成功标准是三平台有可追溯的真实搜索结果，报价可复算，模型建议有证据，部分平台失败可明确降级。推荐仅代表本次已搜索范围，不承诺全网最低价。不包含自动支付、后台长期监控、浏览器抓取和第三方数据服务。

## 当前系统与改动边界

现有 catalog 只读取数据库；模型只提取需求；价格与推荐由规则计算。新系统增加官方平台适配器、搜索编排器、报价标准化与决策模型。沿用现有匿名会话、访问控制、预算限制及推荐快照。人工与演示数据保持独立来源，绝不用于伪装平台成功。

## 接入方式与外部前提

分别使用淘宝联盟/开放平台、京东联盟/开放平台、多多进宝/拼多多开放平台获批的商品搜索、详情及必要的跳转链接能力。不能将文档公开等同于账号已获授权，也不能假定联盟数据覆盖全部商品或个人结算价。

正式实现各适配器前，必须以当时官方文档和应用后台核实接口版本、签名算法、权限、配额、标识符、可返回字段与展示/缓存要求。将核实结果记录到适配器接入说明；旧接口示例不能替代此步骤。不在本设计中硬编码未经验证的接口名称。

每个平台独立配置服务端应用凭证，及其接口实际要求的授权信息和推广位标识。凭证不进入客户端、模型上下文、Git 或日志。无需用户在聊天中粘贴密钥。无凭证时报告未配置；权限不足时报告未授权。模拟响应只能用于测试，真实联调作为独立验收项。

## 模块与数据流

1. 需求模块：提取预算、品类、必需规格、品牌偏好、购买量、是否接受囤货、配送区域，以及按平台区分的会员/首购状态。延续现有数量“零售包数”的语义；新增总用量需求必须使用显式单位，不静默转换旧数据。
2. 搜索规划：模型输出结构化查询，首轮至多两个查询，覆盖精确需求与允许的替代品。规则验证查询长度、品类和数量。模型不可选择请求地址或签名参数。
3. 并行搜索：每个已配置的平台执行相同查询，独立超时、限流与结果状态；首轮每平台最多保留 20 条候选。一个平台失败不阻断其余平台。
4. 标准化：保留平台商品/规格/店铺标识和原始证据，映射到统一报价对象。同平台同规格去重；跨平台同款分组但保留不同卖家的报价。仅标题相似不能认定同款。
5. 报价核算：按可确认的条件计算整数分金额，筛除违反硬约束的候选，构建可比较集合。
6. 补搜：候选不足或关键属性缺失时，允许模型发起至多一次补搜，仍受总调用与时间预算限制。未经数据源证实的模型提取属性标为待确认，不作为已验证事实。
7. 决策：模型从候选 ID 中选择至多三个购买方案，分别对应最低支出、最低单位成本和最符合偏好；允许少于三个、允许无合格结果，不为凑数重复展示。
8. 最终校验：对入选报价进行详情刷新（接口支持时）、重算价格并检查模型引用。变化后重新排序或剔除，不能展示旧理由与新金额的组合。保存不可变快照后返回。

## 适配器与报价契约

适配器提供 capabilities、search、getDetails，以及有权限时的购买链接生成。能力明确区分搜索、规格详情、库存、运费、优惠和购买链接；不支持的字段保持未知。

搜索状态统一为 success、empty、unconfigured、unauthorized、rate_limited、timeout、error。每次搜索保存平台、状态、取数时间、查询与计数；用户能看见覆盖情况。

报价至少包含：平台、商品 ID、规格 ID（未知可空）、店铺 ID（未知可空）、名称、品牌与规格、单包用量/单位、价格口径（确定规格价/起售价/区间价）、币种、商品金额、运费、库存状态、来源链接、采集时间、优惠有效期、条件与证据 ID。未知、未提供与不适用不能混成零或 false。

起售价、未知规格、过期优惠、未确认的会员资格或运费不能构成确定到手价。平台 API 返回也不自动标记为人工核验。字段证据记录来源与时间；仅保留必要响应片段，剔除令牌和个人信息。

## 价格与推荐规则

程序负责总价、优惠、数量、预算及单位成本，模型负责理解偏好、选择候选和解释取舍。

首版支持能够从接口明确表达并校验的单商品优惠；多个优惠只有平台提供明确可叠加依据才组合。跨店满减、未知叠加规则、个性化补贴和未证实的返利不计入确定节省金额。不通过额外购买无关商品制造优惠。

所有推荐满足已知硬约束。已知部分费用已超过预算时直接排除；费用未知的候选只能作为待确认选项，不能称为预算内方案。囤货必须由用户接受；不接受时保持请求数量，接受时仅在用户给定数量/用量上限内枚举，不默认无限购买。

纸品需对齐层数、尺寸、用量，洗衣液需区分质量/体积、浓缩与香型；品质或品牌差异显式提示。不同计量单位不擅自换算。节省金额需与用户指定的有效可比基准比较，无基准不生成节省数字。佣金不参与排序。

## 模型输出与安全边界

模型只输出受 schema 限制的候选 ID、方案类型、理由、条件与证据 ID；展示金额和链接由服务器补齐。拒绝未知候选、伪造证据和违反硬约束的结果。向用户展示简明依据与权衡，不展示内部推理过程。

商品标题、描述及平台响应均是数据，不能成为模型指令。工具调用由服务端允许列表控制，模型不能访问任意 URL。对格式错误或决策失败不进行无限重试，直接使用明确标记的规则排序。没有模型凭证时仍可进行官方搜索和规则比较。

## 时效、成本与失败处理

默认单次平台请求 8 秒超时，仅瞬时网络/服务端错误允许一次重试；权限错误不重试，限流遵守平台重试提示且不超过整次请求预算。整次流程默认 45 秒上限，截止时取消未完成请求并返回已获得且校验过的结果。

每次用户请求最多两轮搜索、12 次搜索尝试（含重试）、6 次详情/链接尝试（含重试）、3 次模型调用（规划、可选补搜规划、最终决策）。分页计入调用上限。所有调用预留预算并记账；达到限制就降级，不额外隐式调用。

价格缓存内部上限 5 分钟，实际还须取优惠到期时间和平台许可缓存期限的最短值；不允许缓存时不缓存。缓存新鲜不代表用户个人结算价格已确认。入选报价刷新失败时显示上次报价时间与未复核状态，取消确定低价/节省断言。

模型与平台均保留按用户及全局配额。三个平台均失败时返回原因和重试入口，可单独使用用户手动录入比较，不以演示数据补齐。日志记录耗时、状态、数量与内部追踪 ID，不记录凭证。

## 存储与界面

添加搜索运行记录、平台结果状态及报价证据，推荐快照关联本次运行。按现有会话归属与 30 天生命周期管理用户搜索记录；共享公开商品缓存不能携带用户地区、资格等私人上下文。

页面展示各平台状态和当前阶段，方案卡展示规格、数量、确定/待确认价格、优惠前提、来源与时间。采用单次有截止时间的请求，前端显示进行中状态，首版不增加任务队列。推荐快照保留当时条件，重新比较产生新快照。

## 验证与交付标准

- 适配器契约测试：依据核实过的官方协议测试签名、错误码、字段缺失、分页和脱敏；固定测试数据明确标记模拟。
- 核算测试：不同规格、起售价、单位差异、运费未知、会员未知、优惠过期/不叠加、数量上限及严格预算。
- 编排测试：三路并发、部分失败、全失败、调用上限、截止取消、缓存过期和刷新价格变化。
- 模型测试：候选/证据伪造、提示注入、超预算推荐、无效 JSON、模型超时与规则降级。
- 界面测试：平台覆盖状态、真实与演示区分、方案证据、快照和隐私访问控制。
- 真实联调：三个平台分别成功搜索并查询真实详情，保存脱敏证据与日期；至少 20 个跨平台案例核对同规格价格和优惠条件，能确认结算价的案例记录结算差异，不能确认的保持待确认。

代码测试通过不代表接口开通。三平台真实联调未完成时，只能报告“连接器已开发，部分/全部平台待授权验证”，不能报告“三平台已经接通”。

## 后续实施顺序
